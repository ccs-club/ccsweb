# Visual and layout audit 006 - 2026-10-04

Antislop was applied after the fact, as requested. This is an audit only. No application source, content, design direction, or production data was changed.

Design Read: bilingual student cybersecurity club site for MUST students, using the declared dark Geist Mono language, dial ENERGY 2 / RHYTHM 2 / MOTION 1.

## Scope and method

- Rendered `/`, `/about`, `/gallery`, `/events`, and `/admin` in English and Mongolian from the production build.
- Checked 14 viewport states from 280x640 through 1366x900, including both sides of the 640px and 940px layout changes, a 683x450 zoom-equivalent viewport, and logged-in admin at 390px and 1366px.
- Re-rendered Events with the real eight-record `data/events.json` archive, not only the browser-test fixture.
- Captured 18 screenshots, measured bounds and touch targets, tested dialogs, locale controls, mobile navigation, keyboard focus, contrast tokens, motion, and authenticated admin layout.
- Ran `npm run build`, `npm run typecheck`, `npm test` (18 assertions), and `npx playwright test` (75 browser tests). All completed successfully. The build logs one inert `@theme` CSS warning and lint logs two existing unused-variable warnings in `anti-slop/audit-005-visual-sweep.mjs`.

Evidence: [`evidence-006-2026-10-04/`](./evidence-006-2026-10-04/). In particular, `home-short-height.json` records range-level text bounds, and `shot-home-en-1366x570.png` shows finding 1.

## Findings

### 1. HIGH - R-03: the home hero clips actual content at shallow desktop heights

At 1366px wide and heights 561px through 593px, `/` retains its single-screen `overflow: hidden` state even though the hero content no longer fits. The top of the first headline line and the final fact line fall outside the hero bounds, so they cannot be reached by scrolling. The 560px media query correctly switches to the compact layout, but the 561px to 593px gap switches it back too early.

Reason: text escapes its container and is hidden at a real responsive viewport range.

Evidence: both locales fail in `home-short-height.json`; `shot-home-en-1366x570.png` visibly cuts the final MUST-CTF fact.

### 2. HIGH - R-03: mobile navigation is a bare hamburger

Below 940px, all four primary destinations move behind a three-line icon with no visible Menu label or persistent primary destination. The control has an accessible name and works after discovery, but that does not make it visible or self-explanatory for touch users.

Reason: the only route-finding control on mobile depends on an unlabeled convention rather than an explicit mobile navigation cue.

Evidence: `shot-home-mn-390x844.png`, `shot-events-production-mobile-en.png`, and `src/app/site-header.tsx`.

## Observations, not numbered fixes

- The Events hero renders `8+` for an archive with exactly eight records. The number is sourced and therefore not a fabricated statistic, but the plus sign is less precise than the available count. This was also documented in audit 005.
- The raw layout scanner records the hero's negative-inset decorative pseudo-element as clipped at several otherwise valid viewports. Range-level text measurement separates that harmless geometry from the real shallow-height failure in finding 1.
- The expected 401 browser-console entry occurs only when deliberately submitting a wrong admin password. The UI shows its localized error message correctly.

## What passed in the inspected scope

- No real horizontal overflow was found across the public-route probes or authenticated admin views. The only raw out-of-bounds element was the intentionally oversized fixed background wash.
- All inspected interactive targets measured at least 44px in both dimensions. Mobile menu open/close, gallery viewer, event details dialog, failed login feedback, and valid admin login worked.
- Fresh keyboard walks on all five routes showed a visible 2px green focus outline for the first ten tab stops. Gallery and event dialogs close with Escape.
- The declared dark palette clears the checked contrast pairs: muted public metadata is 5.97:1 on `#161616`, green is 8.16:1, and control boundaries clear the 3:1 non-text requirement. Existing browser tests also passed the hero contrast check.
- The production archive holds at desktop, tablet, and mobile widths. Year filters remain 44px tall, the carousel exposes a next-card affordance, and its controls work by keyboard and pointer.
- The documented motion is restrained: the slow background wash is the only CSS infinite animation, and reduced-motion styles stop it. The hero canvas also has a reduced-motion path.
- Layout, structure, palette, typography, real photography, identity motif, and CTA language match `DESIGN.md`. No template sections, fabricated social proof, generic FAQ, or dead navigation were found.

## Gate status

Not clean. R-03 fails for findings 1 and 2. No fix has been made. Approve specific numbers, for example `1`, `2`, or `1 and 2`, before implementation.
