# Anti-slop audit 001 — 2026-09-27

Scope: `ccsweb` (Next.js 16.3.6 App Router, Tailwind v4, 30 source files, 1821-line
`globals.css`). Audited by reading every source file, building, running the dev
server, driving both public routes in a real browser at 1440px and 390px, and
running Lighthouse accessibility audits on `/` and `/events`.

## Design Read (inferred, R-37)

Reading this as: bilingual student-club site for MUST ICT students, in a
security-club visual language, dials ENERGY 2 / RHYTHM 2 / MOTION 1.

**Caveat:** no `DESIGN.md` exists and no brand direction was supplied. The dials
above are inferred from `handoff.md`, which names `haruulzangi.mn` as the design
reference and the matrix hero as the identity motif. The site is therefore
direction-backed by a living reference, not direction-free, but the direction is
not written down anywhere in the repo. See finding 12.

## Verdict

This is not slop. It passes the filter with a real margin. It also has four
genuine defects, found by driving the UI rather than reading it, and one
structural gap in its own documentation.

Summary: 1 HIGH, 1 MEDIUM, 10 LOW, plus 4 PASS blocks worth recording.

## Findings

### 1. HIGH — Featured event is the only content on a 55vh section that says "no events yet" (C-3, R-05)

`src/app/events/events-view.tsx:280`, `src/app/globals.css:1691`

`hideFeaturedFromCurrent` is `Boolean(showFeatured && featured && featured.status !== "ended")`.
Every event in `data/events.json` is `ended`, so the featured section always runs
and the "Up next" section is always empty. The page reads, top to bottom:
"Here are your stats" / "No upcoming events are scheduled yet" / a 390px-tall
feature slot for a **December 2025** event / "Past events".

Observed on `/events`: heading "Ирэх болон үргэлжилж буй үйл ажиллагаа" (Upcoming
and ongoing events) is immediately followed by "Одоогоор товлосон үйл ажиллагаа
алга" (No upcoming events are scheduled yet), then a featured card labelled
"Дууссан" (Ended). The club's most prominent event slot advertises something
already over, and the page's only forward-looking section is empty.

Fix: when the featured event is `ended`, drop the featured section entirely and
let the archive carry it. `showFeatured` should require
`featured.status !== "ended"`, and the archive filter that removes the featured
id should follow the same condition.

### 2. MEDIUM — The events hero is a 76px headline over a 3-column stat bar that repeats the home page (C-3, R-20)

`src/app/events/events-view.tsx:236`, `src/app/page.tsx:81`

`/events` opens with `2019 / 38 / 120+`, the same three figures rendered by
`/stats-grid` on `/`, with the same `club-stats.json` source. A visitor who reads
the home page and follows "Events" gets an identical stats block before they see
a single event. `handoff.md` frames this as a deliberate reference choice
("Stats as a hero element"), so the intent is real, but the execution duplicates
a component rather than earning a second one.

Not a template violation on its own. It is repetition, and the events page has
one job the block does not do: tell a visitor what is happening next.

Fix: on `/events`, either drop the repeated stats or replace them with
archive-shaped facts the page is uniquely positioned to state (event count, most
recent event, years covered). All three are computable from `events.json`, so
this adds no fabricated numbers.

### 3. LOW — `event-cover-compact` is a dead class (C-2, R-31)

`src/app/events/events-view.tsx:94` passes `compact` into a template string, but
`.event-cover-compact` appears nowhere in `globals.css`. The `sizes` attribute
does vary, so the prop is not fully dead, but the class it emits does nothing.

Fix: drop the class, or add the rule that justifies it.

### 4. LOW — `--font-geist-sans` is loaded on every page and never used (R-31, C-1)

`src/app/layout.tsx:8`, `src/app/globals.css:24`

`Geist` is imported, given `--font-geist-sans`, and applied to `<html>`. Nothing
consumes it. `--font-sans` is aliased to `var(--font-geist-mono)`, so the sans
face is unreachable even by intent. The mono-for-everything choice is
defensible for a security club and is the site's actual typographic identity;
what is not defensible is shipping the unused face.

Fix: delete the `Geist` import and the `--font-geist-sans` variable, or alias
`--font-sans` to it and use it somewhere real.

### 5. LOW — Two dead i18n keys, in both locales (C-2)

`src/app/i18n.ts:9,11` and the `mn` equivalents: `nav.home` and `nav.activities`
are never read. `nav.activities` and `nav.events` both resolve to the same
string in Mongolian.

Fix: remove them.

### 6. LOW — `.hero-footnote` is declared twice inside the same media query (R-31)

`src/app/globals.css:769` and `src/app/globals.css:777`

Two separate `.hero-footnote` blocks at 640px, split by an unrelated
`.hero-footnote > span` rule. The second overrides the first's `justify-content`.
Behaviour is correct today; the declaration is split for no reason a reader can
infer.

Fix: merge the two blocks.

### 7. LOW — 15 tap targets are under 44px on mobile (R-03)

`src/app/globals.css:684-717`

All 14 footer links sit at 32px tall (`min-height: 32px`) on a 390px viewport,
plus `.brand` at 42px and `.skip-link` at 38px. Everything else in the mobile
stylesheet was raised to 44px; the footer was missed. The footer is the least
interactive part of the page, so the impact is low, but the rule says 44px.

Fix: `min-height: 44px` on `.footer-contact-links a, .footer-social-links a`
inside the 640px query. `.skip-link` is keyboard-only and exempt in practice.

### 8. LOW — "Register / details" never renders, and no event has a registration URL (C-2, R-26)

`src/app/events/events-view.tsx:173`

The register link is correctly conditional on `event.registrationUrl`, and no
record in `data/events.json` sets one. So the code path is right and the copy is
unused. Not a defect. Recording it because the first person to add a URL will
hit an untested path, and `parseOptionalUrl` accepts any http(s) origin while
every other URL in the app is external-with-`rel="noreferrer"` (this one is
fine, it already has it).

### 9. LOW — Section numbers run 04-07 on `/events` and 01-03 on `/` (R-31)

`src/app/events/events-view.tsx:231,254,282,299` vs `src/app/page.tsx:63,94,135`

The home page numbers About/What we do/Next step as 01/02/03. The events page
continues the same counter at 04/05/06/07, and the archive section renumbers
itself to `07` or `06` depending on whether a featured section rendered
(`{showFeatured ? "07" : "06"}`). The numbers imply a single continuous document
that does not exist: they are page-local, and one of them is conditional. A
visitor who scrolls `/` and sees "03" then opens `/events` and sees "04" has been
told these are chapters of one document.

This is the sharpest slop tell in the codebase: a decorative device doing
structural work it cannot support.

Fix: drop the numbering, or scope it per page. The green number is the accent
doing real work elsewhere; the numeral itself carries no information.

### 10. LOW — `overflow-x: hidden` on `body` masks the hero's intentional overflow (C-4)

`src/app/globals.css:50`

The `.matrix-logo` is deliberately larger than the viewport (`width: min(1320px,
140vw)`) and translates to `-50%, -50%`. Measured at 1141px: it spans -90 to
1230, i.e. 89px of overflow on each side. `body { overflow-x: hidden }` clips
it, so no scrollbar appears. Verified: `document.documentElement.scrollWidth`
equals `clientWidth` at both 1141px and 390px.

This works, and it is the correct mechanism. Recording it because the anti-slop
rule set treats hidden overflow as a smell, and the next person to add a
horizontal element will not know the clip is load-bearing. A one-line comment
saying so would cost nothing.

### 11. LOW — Boilerplate assets from the Next.js template are still in `public/` (C-3)

`public/next.svg`, `public/vercel.svg`, `public/globe.svg`, `public/window.svg`,
`public/file.svg`

Confirmed unreferenced: `grep` over `src/` returns nothing. `public/ccs-logo.png`
and `public/ccs-logo-with-text.png` are the real assets;
`ccs-logo-with-text.png` is also unused (`ccs-logo.png` is the one referenced).

Fix: delete the five template files and the unused logo variant.

### 12. MEDIUM — No `DESIGN.md`, so the design direction lives only in a handoff note (R-37, R-31)

`handoff.md:36` carries the real design direction: reference site, compactness
target (~2900px), stats-as-hero, year grid, dark palette. None of it is in the
repo as a document the design system can be read against. `globals.css:3` says
`Design tokens lifted from the reference` and stops there, with no statement of
what the reference is or why these particular values.

The site is not direction-free, so this is not a draft. But the direction is
undocumented, which means the next change has no written standard to hold
against, and R-31 ("write the reason down") has nowhere to live.

Fix: a short `DESIGN.md` with identity, the three dials, the palette with
reasons, and the reference. Antislop suggests the user authors it; the agent
transcribes.

## PASS records (evidence, not findings)

### R-02 — em dash: PASS
`grep -rno "—" src/` returns 0 matches. Copy uses commas, periods, colons,
parentheses.

### R-17 / R-36 / C-5 — sourced numbers only: PASS
Every figure traces to `src/data/club-stats.json`, which carries its own
provenance: `"source": "CCS 2025-2026 annual report, slides 2, 18, 22, and 36"`.
Event counts, dates and participant numbers come from `data/events.json`, real
event records. No "10K+ users", no uptime claims, no testimonials anywhere in the
project, so R-18 and R-28 have no surface to fail on.

### R-18 / R-28 — no testimonials, no FAQ: PASS
Neither section exists. Nothing fabricated to remove.

### R-23 / R-38 — no assumed assets: PASS
The only brand asset is the club's real logo. The hero is a canvas re-sampling
`ccs-logo.png` pixels (`matrix-logo.tsx:56`), so the identity motif is derived
from the real logo rather than drawn. Event covers are real club photographs
imported from Google Drive into `public/events/`, verified 200 on all five.

### R-24 — navbar links resolve: PASS
Enumerated every interactive element on `/`. Desktop nav: `/#about`, `/events`,
external CTF. All three destinations exist. No ghost links, no "coming soon"
placeholders.

### R-25 — contrast: PASS
Computed every foreground token against every surface it lands on. Worst case
is `--fg-4` `#8c8c8c` on `--surface-3` `#262626` at **4.5004:1**, which clears
AA normal text (4.5:1) by four thousandths. Everything else is 5.07:1 or
higher. Accent green `#00c950` on `#04120a` is 8.64:1. Note: green on pure white
is 2.22:1, which fails, but no text is ever green-on-white here (`.button-primary`
inverts to near-black-on-green instead). Lighthouse accessibility returned 100 on
both routes, independently.

The 4.5004 margin is worth knowing about. It is a pass, but it is one rounding
step from a fail, and `--surface-3` is the surface the year-filter buttons sit
on. Consider nudging `--fg-4` to `#909090` when something in that area is next
touched.

### R-26 — no dead controls: PASS
Every anchor on `/` and `/events` has a real `href` to a real destination, real
external URL, `tel:`, or `mailto:`. Every button either toggles (locale,
year filter, mobile menu) or submits a form. Verified the mobile `<details>`
menu opens and closes and its panel receives pointer events. Zero console errors
on both routes.

### R-27 — three states: PASS
`events/loading.tsx` and `events/error.tsx` both exist with real copy in both
locales and a working `reset` button. Empty states exist for upcoming events
(two distinct strings, one for "nothing at all", one for "nothing besides the
featured event") and for the year filter and the admin event list. Admin has
`loading.tsx` and `error.tsx` too.

### R-32 — keyboard: PASS
A `:focus-visible` outline of 2px solid green at 3px offset is defined once, at
`globals.css:32`, covering `a, button, input, select, textarea, summary`. No
`outline: none` anywhere in the file. Every interactive element reports
`tabIndex: 0`. The mobile menu is a native `<details>`, so it is keyboard
operable and Escape-closable for free.

### R-33 — no patch scripts: PASS
No `.py`, `.sh`, or patch script in the repo. The AGENTS.md block is
`next dev`'s own, verifiable at
`node_modules/next/dist/server/lib/generate-agent-files.js`.

### R-03 — mobile: PASS
At 390px: `scrollWidth === clientWidth`, zero overflowing elements, no
horizontal scroll. The one intentional overflow (the matrix) is clipped
deliberately. `.program-card` reflows to two columns, `.stats-grid` and
`.event-details` collapse to one, the desktop nav is replaced by the `<details>`
menu. 44px targets are honoured everywhere except the footer (finding 7).

### R-21 / R-34 — theme: PASS
No theme toggle is shipped, so there is no half-working mode. The dark palette
has a real reason: a security club, and the design reference is dark. One
palette, fully implemented, no fallback path to break.

### R-30 / R-20 — not a clone: PASS
Swapping the logo and name does not produce a recognisable Linear or Vercel.
The identity is specific and earned: monospace throughout, a green
single-accent (`#00c950`, the only chromatic colour in the entire stylesheet),
numbered section labels, and a live pixel-field rendering of the club's own
shield. That motif could not be lifted onto another product.

### R-11 — radius: PASS with one caveat
`--radius: 14px` is the system. Cards, sections and forms follow it. Pill shapes
appear in exactly the places that are semantically toggles or chips: nav links,
locale toggle, join button, event status, event tags, year filter. The CTA
`.button` is 999px, which is pill-shaped but conventional for a single primary
action pair. Variation exists (7px on inputs and admin notices, 10px on the
mobile panel, 6px on skip-link, 8px on the config note, 14px on cards), so
radius is doing hierarchy work rather than flattening everything.

### R-16 / R-15 — copy: PASS
No "Get Started", "Learn More", "Seamless", "Revolutionary", "AI Powered".
CTAs are specific: "About the club", "Join the club", "Try the CTF", "What we
do", "Register / details", "Create and update public event listings without
editing the source code". Each names the actual action.

### R-05 — layout templates: PASS
Not a Hero + 3 cards + testimonials + FAQ page. The home page runs
hero / split statement + stats band / numbered list / centered closer, four
distinct compositions. The stats band and the program list both use the
one-pixel-gap border trick, which is a system, not a repetition. No pricing, no
logo bar, no fake terminal, no bento grid.

### R-10 / R-13 — glassmorphism and glow: PASS
`backdrop-filter` appears once, on the sticky header, which is the one element
that genuinely overlaps content while scrolling. No glow anywhere. The
`rgba(0,201,80,...)` values are all focus rings, hover states and status tints on
a dark base, not glows.

### R-19 / R-08 — motion: PASS
Motion is confined to the matrix canvas, which is the identity itself, and it
respects `prefers-reduced-motion` (static render, no rAF loop) both on load and
on live change. Everything else is 150-200ms colour and background transitions.
Arrows appear on CTAs, program cards and the register link, all pointing at real
destinations. No floating, bouncing, or staggered reveals.

### R-35 — verified by running: PASS
`npm run build` compiles clean in 226ms, TypeScript clean, all 9 routes
generated. Dev server driven in a real browser on both routes at both widths.
Every interactive element enumerated and its destination or behavior confirmed.
Lighthouse: accessibility 100, best practices 100, SEO 100 on `/`; same on
`/events`. Console: two messages on `/`, both dev-only (React DevTools notice,
HMR connected).
