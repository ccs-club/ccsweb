Quality Locks are LOW.

### 1. HIGH - R-03, R-32 - the first mobile media query is unreachable

A stray brace closes `@media (max-width: 640px)` at `src/app/globals.css:1197`
and immediately opens `@media (max-height: 560px) and (min-width: 641px)` at
`:1203`. Every rule from `:1236` to the end of that block is now gated on a
window that is **wide and short**, which is the opposite of a phone. This is a
regression introduced in the previous session, and it was reported there as
verified across breakpoints, which it was not.

Measured at a 408px CSS viewport on `/about`:

| Selector | Intended | Actual |
|---|---|---|
| `.program-card` | `1fr 38px` | `54px 150px 44px` |
| `.program-copy` width | full column | **150px** |
| `.stats-grid` | `1fr` | `173.5px 173.5px` |
| `.site-footer` padding | `44px 20px` | `64px 32px 58px` |
| `.text-link` min-height | `44px` | `0px` |
| `.footer-contact-links a` min-height | `44px` | `36px` |

The program description is being rendered 150px wide on a phone, which is the
single most visible symptom. Fix is to move the `}` so the block closes after
its last rule and the landscape query is a separate block.

### 2. HIGH - R-03, R-32 - three control groups under 44px on touch

Two of the three are consequences of finding 1. The third is independent:

- `.gallery-viewer-button` measures **40x40** at 390px and has no mobile
  override. This is the previous/next/close control in the new photo viewer, so
  the three controls a thumb must hit to operate the gallery are all short.
- `.text-link` at 0px and `.footer-contact-links a` / `.footer-social-links a`
  at 36px, from finding 1.

`.gallery-viewer` also stacks its bar to a column below 640px, which was the
right instinct and should have carried the button size with it.

### 3. HIGH - R-25 - hero text can land on the dot field

`DESIGN.md` states "The hero logo is never obscured." The mechanism is that
`matrix-field.tsx` suppresses dots only inside the shield, so the copy reads
against empty black. The shield is sized
`min(1080, width * 1.1, height * 0.96)` at `matrix-field.tsx:135`, so on a short
window the height term collapses it while the copy keeps its size.

At 740x360 the shield computes to **284px**, and the hero facts row spans
172px to 565px. Screenshot confirms dots under the `FOUNDED 2019` and `120+`
labels. Those labels are `--fg-4` at 10.5px; the brightest dot composites to
`#b3b3b3`, which is **1.60:1** against that text. The dots are sparse so this is
a worst-case-pixel failure rather than a typical one, but the rule asks for the
whole area the text passes over, and this area fails.

Note for the record: `anti-slop/audit-001-2026-09-27-followup.md` states a
62%x52% radial scrim was restored to fix exactly this. No such rule exists in
the current stylesheet. Either it was lost or the note is wrong, and either way
the mitigation `DESIGN.md` relies on is not in the code.

### 4. HIGH - R-27 - the gallery has no empty state

`src/app/about/photo-gallery.tsx` renders the heading and an empty `<ul>` when
`gallery.json` has no plates. The section would read "Everyone here is a member"
over nothing. There is no empty, loading or error branch, and no `length === 0`
check anywhere in the file.

This is not hypothetical for the new route: `/gallery` needs to exist as a real
page, and a route whose whole reason for existing is a photo grid is exactly
where an empty state matters. When `/gallery` is built it should handle all
three, and `photo-gallery.tsx` should be shared rather than duplicated.

### 5. MEDIUM - R-25 non-text contrast - component borders at 1.22:1

`--line` is `rgba(255, 255, 255, 0.1)`, which composites to `#2c2c2c`:

| Pairing | Ratio | Required |
|---|---|---|
| tile / card border on `--surface` | 1.32:1 | 3:1 |
| `.button-quiet` border on `--surface-2` | 1.22:1 | 3:1 |
| `.button-quiet` fill on `--bg` | 1.16:1 | 3:1 |

`.button-quiet` is the worst case because both its fill and its border are
invisible, so it is identifiable only by its text label. It is the secondary
CTA on the home hero and on the join panel, and it is the only thing on those
screens that is not the white primary button.

The project already solved this exact class of problem for admin inputs by
introducing `--control-border: #626262` at 3.25:1, per `review.md`. The same
token is the obvious fix here.

### 6. MEDIUM - R-05, R-14 - the gallery grid ends on a hole

Eighteen plates render as one lead plus seventeen tiles. Seventeen does not
divide by three, so the final row holds two tiles and an empty cell. Visible in
the render and it reads as something failed to load.

Separately, three of the eighteen sources are not photographs but designed
poster frames with baked-in green brand bands and printed dates
(`founding-2020`, `ccs-members-2022`, `early-members`). They sit unframed
beside fifteen plain photographs, so the grid mixes two different artefacts.
That is a content decision, not a bug, and it belongs to the club.

### 7. MEDIUM - R-23, R-36 - captions are unconfirmed inference

Every caption and alt string in `gallery.items` was written by the agent from
filenames and from text legible inside the images. "BANKSEC #6, May 2025",
"CCS TALK, 2024", "Founding members, November 2020" and the years on the rest
are inferences, not club-supplied copy. `data/events.json` corroborates the
BANKSEC #6 and MUST-CTF 2025 entries but nothing corroborates the others.

Nothing here looks fabricated and nothing is invented, so this is not an R-38
violation. It is a verification gap. A caption that names the wrong event is
worse than a vague one, so at least one member should read the eighteen captions
against the eighteen photographs before launch. Two sources were already held
back on content grounds, recorded in `gallery.json` under `omitted`:
`ccs-expo-team-2024.jpg` (a selfie whose foreground face is distorted by the
lens) and `banksec-three-friends-2025.jpg` (stored rotated, so the subjects lie
sideways in a landscape crop).

### 8. MEDIUM - R-06 - wide-tracked uppercase section labels

`ABOUT US`, `GALLERY`, `WHAT WE RUN`, `NEXT STEP`, `THE CLUB`, `UP NEXT`,
`ARCHIVE`, `CONTACT`, `FOLLOW CCS` render at 10-11px with 0.16em to 0.22em
tracking on every section of every page. `antislop-ui` names "uppercase labels
with extreme letter-spacing" as the tell, and R-06 asks for the reason to be
written down.

`DESIGN.md` does give one: "The label reads as one unit, so it carries the
accent itself." Under R-37 direction outranks the filter, so this is not a
failure and I am not asking for a change. It is listed because the rule names
it and the owner should know the label is a rule-named pattern rather than an
unexamined default.

### 9. LOW - antislop-code - box-drawing banner comments

Thirteen section comments in `src/app/globals.css` use box-drawing rules, for
example `/* ── Hero ─────... */` at line 281. The skill names this pattern
explicitly as decoration that signals a generator rather than an engineer. The
plain comments elsewhere in the file already do the job, including the ones that
explain *why* (`overflow-x: hidden` is load-bearing; the hero facts come from
`club-stats.json`; the accent labels read as one unit). Stripping the rules
leaves the reasons, which is the correct outcome.

## Not findings, recorded so they are not re-raised

- **MOTION 1 against the hero's endless shimmer.** `antislop-ui` treats an
  endless loop as a FAIL at dial 1. `DESIGN.md` explicitly declares the hero dot
  shimmer and the background wash as this project's MOTION 1 content, and the
  canvas already stops its render loop under `prefers-reduced-motion`. Direction
  outranks the filter here. No change.
- **The dot field as a background pattern (R-07).** It is the shield's own
  resampled pixels, not a decorative grid, and `DESIGN.md` says so. No change.
- **Programme numbering `01` `02` `03`.** `DESIGN.md` removed *section* numbering
  because it implied one continuous document. Numbering the three programmes
  inside one list is not that. No change.
- **Both primary buttons ending in an arrow (R-08).** Two per screen, not one per
  button, and the arrow is the site's existing exit glyph. No change.
