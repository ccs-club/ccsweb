# Posts layout audit 008 - 2026-10-05

Antislop remains in Mode 2. This is an audit only. No application source or
Facebook content was changed.

## Scope

- Reviewed the user-supplied desktop capture of local `/posts` populated with
  real selected Page snapshots.
- Traced the rendered geometry to `src/app/posts/posts-view.tsx` and
  `src/app/globals.css`.

## Finding

### 1. MEDIUM - R-14 / C-4: arbitrary Facebook post length creates an empty card surface

The posts list is a two-column CSS grid. Each `.facebook-post-card` has
`height: 100%`, while `.facebook-post-body` expands with `flex: 1`. A long
text-only post therefore sets the row height, and its shorter neighbor becomes
a large, empty bordered rectangle. The supplied desktop capture shows this
above the first row of image posts.

Reason: Page content has intentionally variable length, but the shared card
height treats it as uniform. The empty surface reads as a missing state rather
than an intentional archive layout.

Recommended fix: remove the forced equal-height treatment and let content-heavy
text posts span the reading width. Keep compact or image-led posts in two
columns, preserving source order and avoiding CSS-column masonry, which would
make visual order diverge from keyboard order.
