## Findings

### 1. HIGH - R-03: the narrow footer clips the Hack The Box link

At 280px wide on `/posts?lang=mn`, the visible `Hack The Box` footer link has
a 110px client width and a 138px scroll width. Its final characters are cut
rather than wrapped. The document reports no horizontal scrollbar only because
the page clips horizontal overflow.

Reason: a real interactive label escapes its container and loses readable
content at a supported narrow viewport.

Evidence: [`footer-280.json`](./evidence-007-2026-10-04/footer-280.json) and
[`posts-mn-narrow.png`](./evidence-007-2026-10-04/posts-mn-narrow.png).

### 2. MEDIUM - R-37 / DESIGN.md: the navigation taxonomy now conflicts with the recorded direction

`DESIGN.md` explicitly says the navbar is four items: Home, About, Gallery,
and Events. The new `Posts` link makes it five. The new route is real and
usable, so this is not dead navigation, but the design direction has not been
updated to record that the public information architecture now includes Posts.

Reason: the UI and the written source of design direction disagree. Confirm the
five-item navigation as the intended structure, then update the direction, or
choose another intentional route to the page.

Evidence: `DESIGN.md`, `src/app/site-header.tsx`, and
[`posts-en-desktop.png`](./evidence-007-2026-10-04/posts-en-desktop.png).

## What passed in the inspected scope

- `/posts` uses only admin-selected snapshots. The public browser bundle has no
  `process.env.FACEBOOK_PAGE_ACCESS_TOKEN`, Page-token test literal, or
  `graph.facebook.com` reference. The admin route is protected; an anonymous
  request to `/api/admin/facebook-posts` returned 401 in browser coverage.
- The server client reads only the documented Page fields, validates IDs and
  Facebook-owned URLs, keeps the token server-side, uses a five-minute
  per-instance cache, and serves selected images through a same-origin route.
- The public route has an explicit empty state, loading state, and error state.
  The admin selector has a disabled and explained unconfigured state, a
  refreshing label, an error message, selected-post removal, and a published
  post list when the protected refresh succeeds.
- At 390px and 1366px, the new Posts cards and the admin selection panels fit
  without horizontal overflow or console errors. The public post link and
  every measured new button are at least 44px tall. The green link, muted
  metadata, and body-copy color pairs clear the checked AA contrast thresholds.
- The new route uses the actual shield motif and existing type, palette, card
  shape, and motion rules. It adds no generated people, logo, illustration,
  statistic, testimonial, FAQ, or generic marketing section.
- The new public link resolves, has localized copy, is included in the sitemap,
  and updates document metadata in both locales. The admin actions use native
  buttons and the existing visible focus style.

## Operational verification still needed

The test server intentionally has no Page access token, so its refresh control
correctly remains disabled. Unit coverage exercises Graph response parsing,
cache behavior, unsafe URL rejection, atomic selection writes, removal, and
the anonymous API rejection. Before production release, a site administrator
must perform this protected live sequence with a deployment secret: refresh
published Page posts, select one, verify it appears on `/posts`, remove it,
and verify it disappears. Do not place the token in a browser or a ticket to
perform that check.
