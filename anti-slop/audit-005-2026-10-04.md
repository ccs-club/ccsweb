# Visual audit 005 - 2026-10-04

Antislop applied after the fact (Mode 2 audit), as requested. This is an audit,
not a fix pass. No application source, design direction, or production event
data was changed. New files are this report, its sweep script
(`audit-005-visual-sweep.mjs`), and its evidence folder.

Design Read: bilingual student cybersecurity club site for MUST undergraduates,
in the declared dark Geist Mono language, dial ENERGY 2 / RHYTHM 2 / MOTION 1,
from `DESIGN.md`.

## Scope and method

- Production Chromium rendering of `/`, `/about`, `/gallery`, `/events`, and
  `/admin`, in English and Mongolian.
- Viewports: 312x780, 390x844, 641x800, 768x1024, 940x900, 1366x900.
- 60 layout probes (overflow, clipped text, tap targets), 54 contrast pair
  measurements, 6 state exercises, link/keyboard/motion sweeps, and 24
  full-page screenshots. Measurements ran against the real eight-event
  archive (temporary copy in the test server's store, fixture restored
  afterward), following the audit-003 precedent.
- Contrast pairs composited every rgba background layer from the element to
  the root, so text over layered charcoal bands is measured against its real
  effective ground.
- The first sweep run also reproduced the two console errors seen in the
  e2e suite; both were then traced on a dev build and a prod build (details
  under findings).

Evidence: [`evidence-005-2026-10-04/`](./evidence-005-2026-10-04/).
`measurements.json` (layout), `contrast.json` (54 pairs), `states.json`
(state exercises + console errors), `controls.json` (links, keyboard focus,
animations), `shot-*.png` (24 screenshots).

## Findings

### 1. LOW (R-35, evidence): minified React error #441 on the events error-boundary retry path

Reproduced on the prod build: break the events store, load `/events` (error
boundary renders correctly), restore the store, click "Try again". Recovery
works (the archive renders), but the console records `Minified React error
#441` ("getSnapshot should be cached"). The dev build shows no such error on
the same path, and plain navigation never triggers it. No user-visible harm:
the retry recovers fully, both dialogs close on Escape, no state is lost.
Likely cause: the error boundary remount happens while the router is still
resolving, so `useSyncExternalStore`'s snapshot check trips once under the
prod double-render. Worth a look, not worth churn: if a React/Next upgrade
lands, re-test this path first.

### 2. LOW (R-35, evidence): 401 console noise on a wrong admin password

Submitting a wrong password logs `Failed to load resource: 401` in the
console. The UI feedback is correct (visible error, R-26 PASS), and a 401 on
a failed login is the honest status. Browsers always log failed HTTP status;
there is nothing to fix in the app. Recorded so the e2e console-error
assertion accounts for it.

### 3. OBSERVATION (R-17, honest): the events hero says "8+" when the archive holds exactly 8

`events-view.tsx` renders `${pastEvents.length}+`. The `+` reads as "more
than eight", but the count is exact. It survives R-17 because the number is
real and sourced from `data/events.json`; the `+` is a styling choice that
will start lying the moment someone stops adding events. Recommend dropping
the `+` or wording the label as "8 archived" so the figure stays exact.

### 4. OBSERVATION (DESIGN.md, deliberate): programme rows are numbered 01-03

`DESIGN.md` bans section numbering ("a `01`-`07` counter across two pages
implied one continuous document"). The programme list numbers its three items
01-03. The ban targeted page-level counters; these are list items inside one
section, and `DESIGN.md` explicitly provides for "data-field labels inside
programme rows". Judged consistent with the direction as written. Flagged
only so the next auditor does not re-litigate it.

### 5. OBSERVATION (R-03, tooling): the sweep's "clipped text" hits are the sr-only pattern itself

The 12 clipped-text records are all `.sr-only` spans (1px clip by design).
No real text escapes its container anywhere in the 60 probes.

## Verdict

Clean gate. Two LOW findings are console-noise records, not user-facing
defects; three observations document deliberate choices. Nothing to fix.
The one change worth considering next time the events page is touched:
drop the `+` from the archive count (finding 3).
